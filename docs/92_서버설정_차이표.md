## 2. 🟠 정해 주셔야 할 것

### 2-1. Java 21 을 찾는 방법

- **서버 쪽**
  - `build.gradle`: `vendor = JvmVendorSpec.ADOPTIUM` → **Eclipse Temurin 21 만** 씀
  - `settings.gradle`: `foojay-resolver-convention 0.9.0` 플러그인. 인터넷으로 JDK 를 받는 도구인데, 폐쇄망에서는 받을 수 없음
- **이 저장소**
  - 업체 고정 없음 → PC 에 깔린 아무 JDK 21 이나 씀
  - foojay 를 빼고 `auto-download=false` 를 넣음
  - nh-atms 본 프로젝트(2026-07-28 점검 H-1)와 같은 방식
- **프론트에서 보면**: 차이 없음
- **영향**
  - 서버 방식으로 맞추면 PC 에 Temurin 이 없을 때 "Cannot find a Java installation … Eclipse Temurin" 오류로 빌드가 멈춤
  - 지금 방식은 Jenkins(Temurin 21)·PC 모두 그대로 빌드됨

### 2-2. Gradle 배포판 주소 검사

- **서버 쪽**: `validateDistributionUrl=true`. Gradle 을 받을 주소에 접속해 확인함
- **이 저장소**: `false`(nh-atms 와 같음). 폐쇄망에서 접속 시도를 하지 않게 함
- **영향**: 캐시에 Gradle 8.14.4 가 이미 있으면 둘 다 동작함. `true` 는 캐시가 없을 때 접속 오류가 남

### 2-3. WAR 파일 이름

- **서버 쪽**: `atms-web-0.0.1-SNAPSHOT.war`
- **이 저장소**: `archiveFileName = "${project.name}.war"` → `atms-web.war`
- **영향**: 배포킷 Jenkinsfile 은 `atms-*/build/libs/*.war` 를 모아서 `<모듈>-<버전>-<날짜>-<빌드>.war` 로 이름을 다시 붙임 → 어느 쪽이든 Jenkins 결과는 같음

### 2-4. p6spy(실행된 SQL 을 로그로 보여 주는 도구)

- **서버 쪽**: `implementation` → WAR 에도 들어감
- **이 저장소**: `developmentOnly` → 내 PC `bootRun` 때만 켜지고 WAR 에는 안 들어감
- **영향**: 개발 서버(JEUS) 로그에 SQL 이 찍히는지가 달라짐

### 2-5. Swagger(API 문서 화면)

- **서버 쪽**: 설정 없음 → 기본으로 켜짐
- **이 저장소**: `application-jeus.yml` 에서 `swagger-ui.enabled: false`, `api-docs.enabled: true`
- **영향**
  - 배포킷 상태 확인(`deploy-war.sh` 가 `/v3/api-docs` = 200 을 봄)은 그대로 됨
  - 개발 서버에서 `/swagger-ui` 화면만 안 열림

### 2-6. 필드 암호화(crypto.field, node-forge)

- **서버 쪽**
  - atms-web 이 기동할 때 `/home/atmswas/keys/field-k202611.*.pem` 키 파일이 꼭 있어야 함
  - 프론트에 `node-forge 1.4.0` 이 있음
- **이 저장소**: 로그인 기능이 없어서 암호화 대상(로그인·비밀번호)도 없음 → 설정·라이브러리를 넣지 않음
- **영향**: 이 저장소 WAR 는 키 파일 없이도 뜸. 나중에 로그인 화면이 생기면 서버 쪽 설정을 그대로 가져와야 함

## 3. 🔵 이유 있는 차이 (그대로 둬도 되는 것)

**모듈이 2개뿐이라서** (atms-common + atms-web, 견본 화면용)

- `settings.gradle`: journal·batch·file·if-internal·if-external 을 넣지 않음
- `jeus-common.yml`: `jeus.url.web…ifex` 6개 주소와 `agent-entry`(L4 VIP) 없음 → 다른 모듈을 부르지 않음
- `application-jeus.yml`: `agent.proxy`·`atmf.remote`·`gateway` 없음
- `application-local.yml`: 로컬 게이트웨이 경로 없음

**로그인이 없어서** (설계 §13 Q1, 고정 사용자)

- `jwt.*`, `JWT_SECRET`, `sso.provider`, `init.admin`(관리자 초기 비밀번호)이 없음
- 그 대신 `atms.fixed-user.per-no` 가 있음
- jjwt 라이브러리 없음

**견본에 없는 기능이라서**

- 첨부 업로드(`notice.upload-dir`, `multipart 200MB`), 다운로드 저장소(`download.storage`) 없음: 정본에 첨부 테이블이 없음(Q-02)
- 엑셀 서버 생성(POI) 없음: 엑셀은 프론트 `xlsx` 로 만듦
- gson, prometheus 없음: 쓰는 코드가 없음
- H2 없음: Oracle 만 쓰기로 함

**벤더 기본값 정리**

- `application.yml` 의 벤더 DB 기본 주소(`192.168.28.21:1521/ATMSPDB`, 계정 `ATMS`)를 빼고, 로컬은 `local-common.yml` 하나로 함

**프론트** (`package.json` 은 2026-11-09 "지금 그대로"로 정해짐)

- `package.json`·`package-lock.json`
  - nh-atms 본 프로젝트와 같은 버전으로 고정(예: react `19.2.4`, 서버는 `^19.2.0`)
  - 테스트·목 도구(vitest·msw·testing-library·playwright)가 있고, node-forge 는 없음
- `vite.config.ts`
  - 개발 포트 3100, `/api` 를 모두 8080 하나로 보냄
  - 서버 쪽은 포트 3000 에 모듈별 프록시
- `eslint.config.js`: 규칙 추가(any 금지, 포맷 함수 재정의 금지 등)
- `tsconfig.app.json`: 테스트 타입 추가
- `index.html`: 한국어 제목·`lang="ko"`
